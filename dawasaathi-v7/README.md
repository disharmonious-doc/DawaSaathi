# DawaSaathi v7

A simple Hindi patient-support web app. Prescription and medicine-pack images are analyzed on the backend with OpenAI vision. The patient-facing interface and instructions are in Hindi, while English medicine names are retained internally for matching.

## Changes in v7

- Numbers are displayed with standard Arabic numerals: `1`, `2`, `5`, `15`, etc. They are not converted to Devanagari digits.
- Browser `speechSynthesis` has been removed.
- Hindi voice is generated by the backend through the OpenAI Speech API and returned as MP3 audio.
- A visible **सुनें / फिर सुनें** button remains available even if the browser blocks autoplay.
- The app is ready for public backend hosting. `OPENAI_API_KEY` is read only by `server.py` and is never embedded in `index.html` or `app.js`.
- `render.yaml` and `Dockerfile` are included for deployment.
- A basic per-IP rate limit is included to reduce accidental public API abuse. Configure it with `RATE_LIMIT_PER_HOUR`.
- The latest project prescription mapping remains authoritative: OD, OD BBF, BD, TDS, QID, ABF, BL, AL, AD, OD HS, 5 mL/15 mL spoon approximations, MV and BC.

## Run locally on Mac

1. Unzip the folder.
2. Double-click `start.command`.
3. Enter your OpenAI API key when asked, or place it in a local `api_key.txt` file next to `server.py`.
4. The local website opens in the browser.

`api_key.txt` is ignored by Git and Docker and should never be uploaded to a public repository.

## Public hosting on Render

The included `render.yaml` is configured as a single Python web service. The same service hosts both the website and the API, so no API key is exposed to the browser.

### 1. Put the folder in a Git repository

Upload the contents of `dawasaathi-v7` to a GitHub/GitLab/Bitbucket repository. Do **not** upload `api_key.txt`.

### 2. Create a Render web service

In Render, create a new **Web Service** from the repository. Render can also detect the included `render.yaml` as a Blueprint.

The service starts with:

```bash
python3 server.py
```

`server.py` automatically binds to `0.0.0.0` when it detects Render and uses Render's `PORT` environment variable.

### 3. Add the API key as a secret environment variable

In Render > your service > Environment, add:

```text
OPENAI_API_KEY = your OpenAI API key
```

Do not put the value in `render.yaml`, JavaScript, HTML, GitHub, or Dockerfile.

The included Render configuration also uses:

```text
OPENAI_MODEL = gpt-5.6-sol
OPENAI_TTS_MODEL = gpt-realtime-2.1-mini
OPENAI_TTS_VOICE = marin
RATE_LIMIT_PER_HOUR = 60
```

### 4. Deploy

Render will give the service an HTTPS `onrender.com` URL. Because frontend and backend are served from the same origin, the browser calls endpoints such as `/api/analyze-prescription`, `/api/analyze-medicine`, and `/api/speak` without ever seeing the OpenAI API key.

## Voice implementation

The frontend sends only the final Hindi instruction text to `/api/speak`. The backend calls OpenAI's speech endpoint and returns MP3 audio. The prompt asks for clear, calm Indian Hindi and for medicine names written in Devanagari to be pronounced as written.

If the configured current speech model fails, the backend temporarily attempts `gpt-4o-mini-tts` as a compatibility fallback. The primary model remains `gpt-realtime-2.1-mini`.

The website discloses that the spoken voice is AI-generated.

## Security / public deployment notes

- Keep `OPENAI_API_KEY` only in the hosting platform's secret environment variables.
- Do not commit `api_key.txt`.
- The included rate limiter is only a basic cost-control measure. For a real public/clinical deployment, add stronger abuse protection, logging, authentication or access controls where appropriate, and budget/rate alerts in the OpenAI project.
- Prescription images contain sensitive health information. Before real clinical deployment, confirm patient consent, institutional privacy/security requirements, data retention policy, and applicable legal/compliance requirements.
- This prototype is patient support software, not a substitute for clinical review. Unclear matches or doses should be confirmed with a doctor or pharmacist.
